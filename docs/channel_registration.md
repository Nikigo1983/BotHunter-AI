# BotHunter AI — Channel Registration

## Обзор

Регистрация Telegram-канала выполняется через команду `/connect` и отправку Chat ID.

**Важно:** регистрация **не зависит от FSM**. FSM используется только как подсказка интерфейса после `/connect`.

---

## Команда `/connect`

Показывает инструкцию:

1. Добавить бота в администраторы канала.
2. Выдать права **Invite Users** и **Manage Join Requests**.
3. Отправить Chat ID канала.

После `/connect` FSM переходит в `ConnectChannelStates.waiting_for_channel_id` — это UX-подсказка, не обязательное условие регистрации.

FSM хранится в **Redis** (`RedisStorage`), состояния переживают перезапуск бота.

---

## Регистрация по Chat ID

Handler: `app/bot/handlers/connect.py`

Если сообщение пользователя совпадает с форматом:

```
^-100\d+$
```

(с учётом пробелов по краям), бот вызывает `ChannelRegistrationService.register_channel()` **независимо от FSM**.

Примеры:

| Сообщение | Действие |
|-----------|----------|
| `-1004286145697` | регистрация |
| `  -1001234567890  ` | регистрация |
| `-123456` | игнорируется |
| `hello` | игнорируется |
| `Chat ID\n\n-100...` | игнорируется |

---

## Ответы бота

**Успех:**

```
✅ Канал успешно подключён.
```

**Ошибка** (нет прав, канал не найден, уже подключён и т.д.):

```
❌ Не удалось подключить канал.
Причина: ...
```

После успешной регистрации FSM очищается.

---

## Устойчивость

| Сценарий | Регистрация работает? |
|----------|----------------------|
| После `/connect` | Да |
| Без `/connect` | Да |
| После рестарта бота | Да (регистрация); FSM UX сохраняется в Redis |
| После `/debug_chatid` | Да |
| После потери FSM | Да |

---

## Бизнес-логика

`ChannelRegistrationService` (`app/services/channel_registration.py`):

- проверка Chat ID через Telegram API;
- проверка прав бота;
- запись в `telegram_channels`;
- ошибки в `channel_connection_errors`.
